# Scan Model Guidance

Before creating a chat-started desktop scan, reviewing source, or calling the Deep coordinator, give any applicable model guidance once for the top-level scan. Independent workers and resumed phases do not repeat it. When the CLI or SDK launch instructions say model guidance was already handled, skip this advisory. Model changes are optional; delivering an applicable nudge is required.

Call `get_codex_security_model_guidance` when available. It reads the effective model and reasoning effort supplied by the current host and queries the Codex model picker catalog without starting a turn. Use those effective settings instead of a saved scan's launch settings or a base configuration file. If the tool or metadata is unavailable, use only effective settings explicitly supplied by the host. Unknown settings are not evidence that the model is old or that its reasoning effort is low. An unavailable advisory never blocks a scan or becomes a capability-preflight issue.

Use the tool's catalog-backed recommendations, or the current host's available-model catalog when it is exposed. Prefer its explicit `upgrade` or `upgradeInfo.model` recommendation and targets present in the user's picker. Follow available upgrade links to the latest recommended release, without cycling. The catalog's non-cyber default is also a supported scanning recommendation, but it does not establish release order. Do not infer release order from picker order, the default model, or unfamiliar model names, and do not recommend an unavailable model. If upgrade information is absent, do not claim that a later release is available.

- For a cyber model other than Astra cyber, explain that it is designed for dynamic exploitation and may produce worse static vulnerability-scanning results. Recommend the latest available non-cyber model supported by the catalog's upgrade information; when a specific recommendation cannot be established, say "the latest non-cyber model available in your model selector." Astra cyber is exempt from this warning.
- When an available recommended newer release is established, include that model in the combined suggestion for better scanning results. Do not steer them to another non-Astra cyber model for scanning.
- When the effective reasoning effort is `none`, `minimal`, `low`, `medium`, or `high`, include `xhigh` in the combined suggestion for the best results. Check the host's supported efforts when available. If support is unknown, make the suggestion conditional on `xhigh` being offered in the selector. Leave `xhigh` and higher efforts unchanged; do not classify unfamiliar efforts as lower.

An applicable tool result is not itself user-visible. If it contains only a warning without an actionable recommendation for a newer model or `xhigh` effort, send the warning as one short commentary paragraph and continue. If it contains an actionable model or effort recommendation, use the tool's complete combined question in the interactive path below; keep any warning in that same question. Do not separately send the question as commentary, edit configuration, switch models, or create another task on the user's behalf.

For a new interactive desktop scan started in chat, present an actionable combined question through one blocking input form before creating a scan or doing source review. Prefer native `request_user_input`; if it is unavailable or errors, call `request_codex_security_user_input`. Pass the same single question with `id: "model_guidance"`, `header: "Scan settings"`, and two choices: **Change settings (Recommended)** ("Choose a model or reasoning effort in the app, then resubmit the scan") and **Continue current settings** ("Start the scan with the model and effort currently selected"). If both input tools are unavailable or error, ask the combined question in plain chat and stop this turn for an explicit reply. If an input request is declined or cancelled, stop without inferring a choice. Do no scan work while waiting. Only an explicit **Continue current settings** answer permits starting the scan with the current settings. On **Change settings**, stop before creating a scan and tell the user to choose the model or reasoning effort in the app selector, then resubmit the scan request with those settings. Do not repeat the advisory after an explicit choice on the resumed request.

For an existing native Security tab scan, its model and effort were selected when the durable scan was created. Send the tool's combined *declarative* advisory as commentary, state that a selector change would apply to a future scan, and continue this already-started scan without opening a blocking question. In a headless host, send the declarative advisory once and continue with the selected settings. The dedicated Codex Security CLI owns one combined interactive yes/no prompt and applies accepted choices for that scan.
